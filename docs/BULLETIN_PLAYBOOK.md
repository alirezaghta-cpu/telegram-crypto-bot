# آموزش و رزومه — ربات تلگرامی بولتن اقتصادی دوزبانه

> **English summary:** A production-tested bilingual (Persian/English) Telegram market-bulletin bot: 4 scheduled posts/day with live prices, rial valuations, news, charts and alerts. This document is the full playbook — architecture, data sources, schedule, every bug we hit with its fix, security checklist, and setup guide. Built and operated end-to-end; deployed on Railway; no credentials are included in this repository.

**ربات:** @Alienpanelsbot — **کانال:** @GalaxiesDrop — **وضعیت:** پایدار و در حال اجرا (اکتبر ۲۰۲۶)

---

## ۱) شناسنامه پروژه

- هدف: بولتن خودکار روزانه، دوزبانه (فارسی + انگلیسی)، قیمت‌های لحظه‌ای، واچ‌لیست، هشدار قیمت، اخبار و چک روزانه — کاملاً خودکار و سر ساعت.
- اصل طلایی: **چهار پست روتین (دو روز + دو شب) هرگز نباید متوقف شود.** ارسال دیرتر مشکلی ندارد، کنسل شدن نه. هر باگی که روتین را تهدید کند باید فوراً به مالک اطلاع داده شود.
- چهار پست: ۲ فارسی (بازار داخلی/ریالی، صبح و شب) + ۲ انگلیسی (UTC/اروپا، morning & market close).
- هر پست آلبوم تصاویر خودش را دارد: ۴ نمودار/تصویر کاملاً مجزا در هر دور، مرتبط با خبرهای همان پست.
- متن: ارقام فارسی در نسخه فارسی؛ تاریخ/ساعت نسخه فارسی = شمسی + تهران؛ نسخه انگلیسی = UTC. قالب روزنامه‌ای با بخش‌بندی یکدست.
- قیمت ریالی: دلار، طلا، نقره، نفت حتماً با معادل ریالی. **رمزارزها فقط دلاری.**
- هشتگ‌ها: مرتبط با خبر همان پست، هر بار متفاوت، **بدون تکرار بین پست‌ها**.
- اخبار: فارسی = مهم‌ترین اخبار داخل ۲۴ ساعت؛ انگلیسی = اخبار جهان/اروپا. در نبود خبر، پست روتین حذف نمی‌شود.

## ۲) زمان‌بندی (ساعت جهانی UTC)

| رویداد | UTC | تهران |
|---|---|---|
| بولتن صبح (فارسی + انگلیسی) | ۰۴:۰۰ | ۰۷:۳۰ |
| چک قیمت/هشدار | ۰۵:۰۰، ۰۹:۰۰، ۱۴:۰۰، ۲۱:۰۰ | ۰۸:۳۰، ۱۲:۳۰، ۱۷:۳۰، ۲۴:۳۰ |
| بولتن شب (فارسی + انگلیسی) | ۱۹:۰۰ | ۲۲:۳۰ |

**قانون تعدیل چرخه:** بولتن‌ها خودکار تریگر نمی‌شوند؛ بعد از هر چرخه، زمان چرخه بعدی باید روی رویداد بعدی + ~۲ دقیقه تنظیم شود. اولویت مطلق: بولتن شب ۱۹:۰۰ UTC. پس از هر ارسال، نتیجه (شماره پیام، ok/failed) ثبت و در صورت شکست تکرار می‌شود.

## ۳) منابع داده (تأییدشده — بدون نیاز به کلید)

| داده | منبع |
|---|---|
| نرخ دلار/لیر (بازار آزاد، تومان) | آرشیو روزانه GitHub: `raw.githubusercontent.com/SamadiPour/rial-exchange-rates-archive/data/gregorian_imp.min.json` (به‌روزرسانی شبانه؛ ×۱۰ = ریال) |
| اونس طلا و نقره | `api.gold-api.com/price/XAU` و `api.gold-api.com/price/XAG` (JSON زنده) |
| نفت برنت | جست‌وجوی وبی قیمت لحظه‌ای (بدون API رایگان پایدار) |
| بیت‌کوین | `api.coinbase.com/v2/prices/BTC-USD/spot` + کندل روزانه `api.exchange.coinbase.com/products/BTC-USD/candles?granularity=86400` |
| اتریوم | `api.coinpaprika.com/v1/tickers/eth-ethereum` (شامل تغییر ۲۴ ساعته) |
| شاخص ترس و طمع | `api.alternative.me/fng/?limit=14` |
| اخبار فارسی و جهانی | جست‌وجوی وب بر اساس زبان هر پست |
| نمودارها | QuickChart — حتماً `POST /chart/create` تا URL کوتاه بگیرید |

نکته: `tgju.org` از برخی محیط‌ها قابل دسترسی نیست؛ آرشیو GitHub جایگزین مطمئن است.

## ۴) تاریخچه باگ‌ها و راه‌حل‌ها (درس‌آموخته‌ها)

1. **آلبوم تلگرام ۴۰۰:** فیلد `media` (نه `photo`) در InputMedia. ✅ حل شد.
2. **URL بلند QuickChart → شکست دانلود تلگرام:** راه‌حل `POST /chart/create` و استفاده از URL کوتاه `zf-`. ✅ حل شد.
3. **کامای داخل float در `fetch_world` (قیمت طلا) → نمایش خراب:** رفع اعشار قبل از تبدیل. ✅ حل شد.
4. **push از طریق base64 با LLM → تک‌حرف خراب در فایل:** فقط blob متنی ساده (utf-8) استفاده شود. ✅ قانون شد.
5. **رفرانس‌های Git خام:** فایل‌های با `/dev/null` نادیده گرفته می‌شوند ولی باید آپدیت شوند. ✅
6. **اولین بولتن صبح با تأخیر رفت (۰۷:۲۱ به‌جای ۰۴:۰۰):** چرخه به رویداد بعدی عقب ننشسته بود → **قانون تعدیل چرخه بعد از هر سیکل.** ✅
7. **`gold-api.com/price/XAG` مسیر نادرست (404):** به منبع معتبر برگشت؛ مسیر `gold-api.com/price/XAG` دوباره تست نشود. (نسخه درست فعلی: `api.gold-api.com/price/XAG`.) ✅
8. **QuickChart `ticks.callback` به‌صورت رشته → HTTP 400 با بدنه PNG → خطای تلگرام «failed to get HTTP URL content»:** هرگز تابع `function()` داخل کانفیگ نمودار قرار ندهید؛ محور ساده بدون callback. ✅ حل شد (۲۰۲۶-۱۰-۰۸).

## ۵) چک‌لیست امنیتی (غیرقابل مذاکره)

1. هیچ‌گاه توکن ربات تلگرام، PAT گیت‌هاب، توکن Railway یا شناسه کانال خصوصی در کد/ریپو/مستند عمومی/چت عمومی قرار نگیرد.
2. مستند عمومی فقط آموزش راه‌اندازی بدون هیچ اعتبار واقعی است (مثال جای‌گذاری‌شده مثل `<BOT_TOKEN>`).
3. اعتبارنامه‌ها فقط در متغیرهای محیطی امن ( Railway env / vault ذهن ) نگهداری شوند؛ هر credentialی که در چت لو رفته باید تعویض شود.
4. رمز عبور دیتابیس قوی و در env باشد؛ توکن ربات هرگز در فایل ریپو نباشد.

## ۶) نحوه راه‌اندازی

```bash
git clone https://github.com/alirezaghta-cpu/telegram-crypto-bot.git
cd telegram-crypto-bot
pip install -r requirements.txt
export BOT_TOKEN=<BOT_TOKEN>        # از BotFather بگیرید؛ هرگز کامیت نکنید
export CHANNEL_ID=@your_channel     # کانالی که ربات ادمین است
python main.py
```

- ربات باید در کانال **ادمین** باشد تا اجازه ارسال پیام/رساله داشته باشد.
- استقرار: Railway از همین ریپو با branch `main` دیپلوی می‌شود؛ سرویس `telegram-bot` در پروژه فعال.
- فایل `.env` را به `.gitignore` اضافه کنید.

## ۷) معماری ماژولار

- `main.py` — نقطه شروع و زمان‌بندی
- `core.py` — هسته ربات و ارسال پیام
- `data.py` — دریافت قیمت‌ها و اخبار از منابع بخش ۳
- `handlers.py` — دستورات کاربری
- `monitor.py` — هشدار قیمت و چک دوره‌ای
- `game.py` / `screens_*` / `strings_fa.py` / `strings_en.py` — بخش تعاملی و چندزبانه
- `ui.py` — دکمه‌ها و رابط کاربری

- پایداری روتین مهم‌تر از فیچر جدید است؛ هر فیچر فقط اگر تهدیدی برای روتین نداشته باشد اضافه شود.
- برای هر داده حتماً منبع جایگزین از قبل شناسایی کنید (مثال: tgju → آرشیو GitHub).

- مستندسازی همان روز باگ‌ها، ارزشش از کد بیشتر است — همین سند از دل همین تجربه بیرون آمد.
